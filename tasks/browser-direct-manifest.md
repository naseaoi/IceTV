# 浏览器直拉清单：拯救「只能用户侧直连」的源站

## 背景

部分源站的视频 CDN 按地区封锁，只放行中国大陆等特定地区 IP。点播清单目前始终经服务端拉取（前端统一请求 `/api/proxy/m3u8`，见 `src/features/play/lib/vodProxyUrl.ts`），后台「直连」只影响分片，所以服务器在海外时这类源整条播放链路不可用；海外出口的上游代理池也无法解决。

已确认案例：电影天堂（key `dyttzy`）

- API `caiji.dyttzyapi.com` 海外可用，搜索与详情正常。
- 清单与分片在 `vip.dytt-kan.com`，生产服务器（美国 IP）请求 `index.m3u8` 返回 403 `The region has been denied`。

## 目标

站长可把源设为「浏览器直拉」：清单、密钥、分片都由用户浏览器直接请求源站，能否播放取决于用户自己的出口 IP；服务端仍负责搜索、详情与鉴权。

## 待调查

1. 受影响范围：盘点现有源中「服务器拉清单失败、但大陆 IP 可播」的有哪些，确认问题的普遍程度。
2. CORS：这类 CDN 对清单、密钥、分片是否返回允许跨域的头。不放行时浏览器直拉同样失败，这决定方案是否可行。
3. 混合内容：HTTPS 站点上的 HTTP 清单 / 分片会被浏览器拦截。
4. 服务端对清单的现有职责在直拉模式下如何处理：
   - URI 改写与缓存（`src/features/play/lib/m3u8-rewrite.ts`、`src/app/api/proxy/m3u8/service.ts`）：hls.js 可自行解析相对地址。
   - 内容校验、鉴权与额度：直拉不经服务端，也不消耗回源额度。
   - 线路检测 `scheduleSourceDirectProbe()`：服务端被封，无法代为检测。
   - 去广告在客户端（`filterAdsFromM3U8()`），不受影响。
5. 源健康检测与选源：服务端探测这类源会失败，需要确认是否会被判为不健康而降级、隐藏或跳过，避免直拉源在选源阶段就被排除。
6. 失败回落：直拉失败时（用户 IP 也被封）给出明确提示或自动换源，不回落到同样会失败的服务端代理。

## 范围

- 后台源配置新增「浏览器直拉」线路选项（与现有 `browser` / `server` / `auto` 并列或扩展 `browser` 语义），站长显式选择，不被自动检测改写。
- 播放运行时按该线路构造清单地址并配置 hls.js。
- 健康检测、选源偏好、自动换源对该线路的适配。

## 验收

- 电影天堂在大陆出口的浏览器中可完整播放（清单 → 密钥 → 分片），服务器日志无该源的清单回源请求。
- 海外出口的浏览器播放失败时，有明确提示或触发换源，不无限重试。
- 其他源的现有线路行为不变。
- 本地验证需要大陆直连出口：开发机流量默认经 Clash TUN 走海外，测试前为相关 CDN 域名设置直连规则。
