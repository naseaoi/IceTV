# 代理池出口能力：按目标选可用出口、支持非标准端口

## 目标

让服务器中转在「本服务器 IP 被拒」时有可用的替代出口，并让代理池能访问非标准端口的媒体地址。完成后：

1. 被按 IP 段封禁的 CDN（见下方 444 组）经服务器中转可播。
2. 开启 `SiteConfig.UpstreamProxyPoolSegments` 后，`:65` 等非标准端口的分片不再因代理池出口失败。

## 背景（2026-11-26 生产实测）

服务器为 RackNerd 美国 IP；代理池网关 `egress-pool-gateway`（`egress_shared` 网络，8081–8084）当前四个出口均为 Datacamp 美国（AS212238）。本机 Oracle 美国出口（AS31898）作对照。

- 线路统计与失败原因已在后台可见（视频源列表的「挽回」率与悬停里的失败原因），可用于验收前后对比。

- 相关组件：`/opt/egress-pool`（git 管理；`scripts/daily-refresh.sh` 生成 `runtime/compose.yaml` 与 `runtime/config.json`，每日 04:17 刷新）、autoroute（`src/egress_pool/autoroute.py`，按 host:port 先直连后转网关）、IceTV 侧 `UPSTREAM_PROXY_POOL` 与 `fetchWithUrlGuard()` 的代理池选择（`docs/deployment.md#上游代理池`）。

## 范围

1. 盘点订阅节点：网段 / ASN 分布，逐个测试对 444 组 CDN 与 `:65` 端口的可达性（只读，不输出节点凭据）。
2. 刷新选节点时把「目标可达性」纳入筛选，或为特定域名指定出口（注意 IceTV 侧 sticky 出口绑定，`docs/playback.md` 第 28 行）。
3. 非标准端口：出口不支持时回退到可用出口或直连，避免整段失败。
4. 订阅里没有合适节点时，评估新增订阅来源，结论交给站长决定。

## 验收

- 444 组任选两个源，经服务器中转能拉到清单与首个分片（生产实测记录）。
- 开启分片走代理池后，ikun / 爱奇艺 `:65` 分片可加载；未开启时行为不变。
- 后台这些源的「挽回」率与失败原因（连接中断占比）在上线后一天内明显改善。
- `/opt/egress-pool` 改动有 git 提交；动 IceTV 容器前先问站长。
