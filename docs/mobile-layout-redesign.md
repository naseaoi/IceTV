# 移动端布局重构设计

## 1. 目标

将移动端从“桌面页面缩小版”调整为符合主流视频 App 使用习惯的布局，同时保留现有桌面端界面和业务链路。

核心目标：

- 首屏优先展示可播放内容，减少导航和装饰占用。
- 全局导航只承担稳定的一级任务，不把电影、剧集、动漫、综艺等频道全部塞进底栏。
- 点播页进入沉浸模式，播放器、选集、详情和换源围绕播放任务组织。
- 数据获取、缓存、播放器、搜索、收藏、历史记录、卡片操作等逻辑继续复用。
- 移动端可适当更换内容编排和组件外观，不复制第二套业务状态。

## 2. 适用范围

移动端定义为视口宽度小于 `768px`，与项目现有 `md` 断点保持一致。

本方案覆盖：

- 全局顶部栏与底部导航
- 首页
- 我的
- 电影、剧集、动漫、综艺、自定义分区
- 搜索与搜索结果
- 收藏列表
- 点播页
- 直播入口的导航归属

桌面端不进行视觉重构，只允许抽取共享数据组件和无视觉副作用的公共逻辑。

## 3. 当前问题

### 3.1 全局导航

- 底栏同时放置首页、电影、剧集、动漫、综艺、直播、自定义分类，数量会随配置增长。
- 每个入口固定占用 `20vw`，超过五项后需要横向滚动，入口发现性和选中状态不稳定。
- 频道入口与一级任务混在一起。电影、剧集等属于内容频道，搜索、我的才属于全局任务。
- 点播页仍显示完整底部导航，播放器可用高度被压缩。
- “我的”页面底栏可能仍高亮首页，路由语义不一致。

### 3.2 首页

- 顶部栏已经有首页品牌和用户入口，正文又出现“首页 / 我的”切换，导航重复。
- “继续观看”沿用通用海报卡片，移动端卡片过高，首屏只能看到少量后续内容。
- 推荐区采用三张大海报横排，信息可读但纵向节奏偏松。
- 电影、剧集等分区已经能从推荐区“查看更多”进入，不需要在首页继续增加重复频道入口。

### 3.3 我的

- 仍保留“首页 / 我的”切换。
- 收藏、统计、历史播放连续纵向堆叠，首屏只能看到收藏，常用的历史播放入口较深。
- 统计卡片更适合独立摘要，而不是占用主要内容流。

### 3.4 分区页

- 页面标题、说明和两行筛选器整体照搬桌面布局，首屏内容占用较大。
- 筛选项全部展开，用户每次浏览都要承受同样的控件高度。
- 三列海报本身可保留，但卡片宽度、间距、标题和标签缺少统一的移动规格。

### 3.5 搜索页

- 搜索入口在顶部栏，搜索结果页又需要独立输入框，返回和清空操作层级不够明确。
- 排序、来源、年份、聚合等控件同时展示时容易拥挤。
- 结果卡片可以复用，但筛选应改为底部抽屉或紧凑工具条。

### 3.6 点播页

- 顶部全局栏、内容标题、标签、播放器、标签栏、选集面板和底部全局栏同时存在。
- 播放页高度被固定导航挤压，播放器不是页面视觉中心。
- 选集面板一次展示大量按钮，移动端浏览成本较高。
- “信息”和“换源”与高频的选集操作同级常驻，占用空间。

## 4. 设计原则

### 4.1 一级导航稳定

底部导航固定为四项：

1. 首页
2. 分类
3. 搜索
4. 我的

直播和自定义分类统一进入分类页，不动态增加底栏项目。

### 4.2 频道与任务分离

- 首页、搜索、我的是用户任务。
- 电影、剧集、动漫、综艺、直播、自定义分类是内容频道。
- 完整频道列表统一从分类页进入；首页推荐区的“查看更多”提供对应频道的上下文直达入口。

### 4.3 播放任务沉浸

点播页和直播页不显示全局底部导航。顶部仅保留返回、标题和必要操作，播放器优先占据可用宽度。

### 4.4 数据逻辑单一来源

移动端只新增布局容器和展示组件，不新增独立的数据请求、缓存、收藏或播放状态。

### 4.5 渐进式改造

优先改造导航和布局容器，再调整各页面内容编排。每个阶段都可以独立发布和回退。

## 5. 全局信息架构

```text
底部主导航
├── 首页
│   ├── 继续观看
│   └── 推荐内容
├── 分类
│   ├── 电影
│   ├── 剧集
│   ├── 动漫
│   ├── 综艺
│   ├── 直播（按配置显示）
│   └── 自定义分类（按配置显示）
├── 搜索
│   ├── 搜索历史
│   ├── 搜索建议
│   └── 搜索结果
└── 我的
    ├── 收藏
    ├── 历史播放
    ├── 观看统计
    └── 设置与账户
```

路由建议：

- 首页：`/`
- 分类聚合页：新增 `/categories`，也可先用移动端专属视图装配现有分区链接。
- 搜索：`/search`
- 我的：`/me`
- 分区：继续使用 `/douban?type=...`
- 点播：继续使用 `/play`

## 6. 全局布局方案

### 6.1 移动端顶部栏

普通页面采用 48px 高度的紧凑顶部栏：

```text
┌──────────────────────────┐
│ 页面标题              操作 │
└──────────────────────────┘
```

规则：

- 首页：左侧品牌名，右侧主题和头像；搜索放到底栏，不再占顶部左侧。
- 分类、我的：左侧页面标题，右侧保留页面相关操作。
- 二级页面：返回按钮 + 标题 + 页面操作。
- 搜索页：顶部栏直接变为搜索框，不再显示品牌标题。
- 点播页：返回 + 截断标题 + 更多操作，不显示主题切换和用户菜单。

复用现有 `MobileHeader`，将其改为配置驱动：

- `variant: 'home' | 'page' | 'search' | 'player'`
- `title`
- `showBack`
- `actions`

### 6.2 移动端底部导航

固定四项，每项等宽，不允许横向滚动：

```text
┌────────┬────────┬────────┬────────┐
│  首页  │  分类  │  搜索  │  我的  │
└────────┴────────┴────────┴────────┘
```

规则：

- 高度 56px，加安全区。
- 图标 22～24px，文字 11～12px。
- 只使用颜色和轻量背景表示选中，不使用尺寸跳动。
- `/douban`、`/live` 和自定义频道统一高亮“分类”。
- `/me`、`/me/favorites` 统一高亮“我的”。
- `/play` 不显示底栏。

### 6.3 内容安全区

- 普通页面顶部预留 48px。
- 显示底栏的页面底部预留 `56px + safe-area-inset-bottom`。
- 点播页使用 `100dvh`，不预留底部导航高度。
- 页面内容统一使用 16px 水平边距；海报网格区域可以缩小到 12px。

## 7. 首页方案

### 7.1 页面结构

```text
┌──────────────────────────┐
│ IceTV              主题 头像 │
├──────────────────────────┤
│ 继续观看              全部 > │
│ [横向宽卡][横向宽卡][...]    │
│                          │
│ 热门电影              更多 > │
│ [海报][海报][海报]            │
│                          │
│ 热门剧集              更多 > │
│ [海报][海报][海报]            │
└──────────────────────────┘
```

### 7.2 继续观看

移动端改为横向宽卡，不使用完整通用海报卡片：

- 卡片宽 220～248px，高 112～132px。
- 左侧封面或横向背景，右侧展示标题、当前集、观看进度。
- 底部使用细进度条。
- 点击卡片继续播放，长按或更多按钮打开现有操作菜单。
- 首页只展示最近 6～10 项，完整记录进入“我的”。

数据和操作继续复用现有 `ContinueWatching`，新增移动展示组件 `MobileContinueCard`。

### 7.3 推荐区

继续复用 `ScrollableRow`、`PosterCard` 和推荐数据。

移动规格：

- 每屏展示约 2.4～2.7 张卡片，而不是强制三张贴满。
- 卡片宽 112～124px。
- 区块标题 18px，区块间距 24px。
- 标题最多两行或单行截断，规则在所有页面统一。
- 首页不展示来源标签，只保留评分、集数等关键角标。

删除首页正文中的 `HomeMineSwitch`。“我的”通过底栏进入。

## 8. 分类聚合页方案

新增移动端分类首页，承载频道入口和最近浏览：

```text
┌──────────────────────────┐
│ 分类                       │
├──────────────────────────┤
│ [电影] [剧集]              │
│ [动漫] [综艺]              │
│ [直播] [自定义]            │
│                          │
│ 最近浏览                  │
│ [横向卡片列表]             │
└──────────────────────────┘
```

频道卡片使用 2 列大按钮，每个按钮包含图标、频道名和简短说明。

第一阶段可以不新增复杂数据，只提供入口；最近浏览属于后续增强。

## 9. 分区列表方案

### 9.1 顶部区域

分区页顶部改为：

```text
┌──────────────────────────┐
│ < 电影               筛选 │
├──────────────────────────┤
│ 热门电影  ·  全部地区   v  │
└──────────────────────────┘
```

- 页面说明移除或放进标题下的一行弱提示。
- 当前主分类和地区显示为紧凑筛选摘要。
- 点击“筛选”或摘要后打开底部抽屉。

### 9.2 筛选抽屉

将现有 `DoubanSelector` 数据和回调复用到移动端 `MobileFilterSheet`：

- 底部弹出，高度不超过 75dvh。
- 每组筛选独立分区，选项使用可换行胶囊。
- 底部固定“重置”和“完成”。
- 修改选项可以即时刷新，也可以在点击完成后应用；第一阶段沿用现有即时刷新行为。
- 桌面端继续使用当前展开式筛选器。

### 9.3 海报网格

保留三列网格，但改为流式宽度：

- 页面水平边距 12px。
- 列间距 10～12px。
- 卡片宽度使用 `calc((100vw - 页面边距 - 列间距) / 3)`，不固定为 96px。
- 海报比例保持 2:3。
- 标题固定两行高度，字号 13～14px。
- 来源标签仅在搜索结果和收藏等有辨识价值的页面显示；豆瓣分区不显示来源标签。
- 评分和集数角标缩小，避免遮挡海报主体。

继续复用 `VirtualizedGrid`、`PosterCard` 和 `CoverImage`。为 `PosterCard` 增加移动展示密度参数，而不是复制卡片业务逻辑。

## 10. 搜索方案

### 10.1 搜索首页

- 顶部栏整体作为搜索框。
- 输入框自动聚焦仅在用户主动进入搜索页时启用。
- 下方依次展示搜索历史、热门或建议内容。
- 清空历史使用二次确认。

### 10.2 搜索结果

```text
┌──────────────────────────┐
│ < 庆余年             清除 │
├──────────────────────────┤
│ 36 个结果        筛选  排序 │
├──────────────────────────┤
│ [海报][海报][海报]          │
└──────────────────────────┘
```

- 来源、年份、聚合开关进入筛选抽屉。
- 排序使用单独的底部菜单。
- 结果总数和当前条件保持一行展示。
- 继续复用 `VirtualizedSearchGrid` 和现有聚合、筛选状态。

## 11. 我的方案

删除 `HomeMineSwitch`，页面由底栏直接进入。

推荐结构：

```text
┌──────────────────────────┐
│ 我的                  设置 │
├──────────────────────────┤
│ 用户摘要 / 当前账号          │
│                          │
│ [收藏] [历史] [统计]          │
│                          │
│ 最近收藏              全部 > │
│ [海报][海报][海报]            │
│                          │
│ 最近播放              全部 > │
│ [横向紧凑记录列表]            │
└──────────────────────────┘
```

规则：

- 收藏、历史、统计作为三项快捷入口。
- 首页只展示收藏预览和最近播放摘要。
- 完整观看统计放到折叠区域或独立页，避免骨架屏占据多个首屏。
- 历史播放继续复用当前 40px 封面列表组件。
- 收藏预览继续复用 `FavoritePreviewSection` 和 `VideoCard` 数据，移动端限制展示数量。

## 12. 收藏页方案

- 使用与分区页一致的三列流式网格。
- 顶部提供返回、标题和排序入口。
- 取消收藏继续使用现有卡片操作。
- 长按卡片打开现有 `MobileActionSheet`。
- 空状态提供“去搜索”和“浏览分类”两个明确动作。

## 13. 点播页方案

### 13.1 沉浸式框架

点播页隐藏全局底栏和普通顶部栏，使用播放专用顶部栏：

```text
┌──────────────────────────┐
│ < 标题                  ··· │
├──────────────────────────┤
│                          │
│       16:9 播放器          │
│                          │
├──────────────────────────┤
│ 第 01 集      选集   换源    │
│ 标题、年份、收藏             │
│                          │
│ [选集内容 / 简介 / 来源]      │
└──────────────────────────┘
```

### 13.2 播放器

- 竖屏保持 16:9，紧贴顶部专用栏下方。
- 不再使用额外的大标题区挤压播放器。
- 标题和来源信息放在播放器下方。
- 横屏时进入播放器优先模式，可隐藏页面其他内容。
- 底部不显示全局导航。

### 13.3 播放信息区

播放器下方第一行：

- 当前集和总集数
- 选集按钮
- 换源按钮
- 收藏或更多操作

第二行展示标题、年份和来源。简介默认折叠为两到三行。

### 13.4 选集

- 不再默认铺满全部集数。
- 页面内展示最近一组或当前集附近的 10～15 集。
- 点击“全部选集”打开底部抽屉。
- 抽屉内复用现有分组、分页和单集切换逻辑。
- 集数按钮最小触控尺寸 44px。

### 13.5 换源与详情

- 换源使用底部抽屉，复用 `SourcesTab`。
- 详情使用折叠内容区或底部抽屉，复用 `InfoTab`。
- 移动端不再常驻“选集 / 信息 / 换源”三标签大面板。
- 桌面端右侧面板保持不变。

## 15. 响应式规格

### 15.1 断点

- 320～359px：紧凑手机。
- 360～479px：标准手机。
- 480～767px：大屏手机和小平板。
- 768px 及以上：维持桌面端布局。

### 15.2 网格

- 320～479px：3 列海报。
- 480～767px：4 列海报。
- 单卡最小宽度 92px。
- 单卡推荐宽度 108～124px。

### 15.3 触控

- 主要按钮最小高度 44px。
- 图标按钮点击区域至少 40×40px。
- 底栏导航项高度 56px。
- 抽屉拖拽条和关闭操作都要有明确点击区域。

### 15.4 字体

- 页面标题：20～22px。
- 区块标题：18px。
- 卡片标题：13～14px。
- 辅助信息：11～12px。

## 16. 状态与性能

- 保留当前封面 600px 预加载策略。
- 首页移动端首屏仅将可见及下一屏关键卡片设置为高优先级。
- 横向列表只加载视口及预加载范围内卡片。
- 骨架屏尺寸必须与最终布局一致，减少跳动。
- 抽屉内容按首次打开动态加载时，应保留现有动态 import。
- 页面切换继续使用现有缓存，不因移动布局引入第二份缓存。

## 17. 无障碍与系统适配

- 支持 `env(safe-area-inset-top)` 和 `env(safe-area-inset-bottom)`。
- 抽屉打开后锁定背景滚动并管理焦点。
- 所有仅图标按钮提供明确 `aria-label`。
- 选中导航使用 `aria-current="page"`。
- 选集、筛选标签使用按钮语义和选中状态。
- 支持深色和浅色主题。
- 支持系统减少动画设置。

## 18. 实施阶段

### 阶段一：全局框架

- 将底栏改为首页、分类、搜索、我的四项。
- 新增分类聚合页。
- 修正所有路由高亮。
- 点播页和直播页隐藏底栏。
- 移除首页和我的页面中的 `HomeMineSwitch`。

验收：所有一级任务在单手操作范围内，底栏不滚动，不随配置增加项目。

### 阶段二：首页与我的

- 继续观看改为移动宽卡。
- 调整推荐卡片尺寸和区块间距。
- 我的页面改为快捷入口、收藏预览、历史预览和统计摘要。

验收：首页首屏能看到继续观看和首个推荐区；我的首屏能进入收藏和历史。

### 阶段三：分区与搜索

- 分区页改为紧凑标题和筛选摘要。

- 搜索筛选和排序迁移到底部抽屉。

### 阶段四：点播页

## 19. 验收标准

### 全局

- 底栏固定四项，无横向滚动。
- 一级页面选中状态正确。
- 点播页和直播页不显示全局底栏。
- 页面内容不被安全区或固定导航遮挡。

### 首页

- 390×844 首屏能看到继续观看和首个推荐区标题或内容。
- 推荐列表横向滑动顺畅，无误触页面纵向滚动。
- 不再出现“首页 / 我的”重复切换。

### 分区

- 筛选器默认收起。
- 首屏至少展示一行完整海报。
- 320px 不出现横向溢出。
- 480px 以上自动提升为四列。

### 搜索

- 搜索框始终处于页面最高交互优先级。
- 筛选和排序不会挤压结果网格。
- 键盘弹出时结果和操作按钮仍可用。

### 我的

- 收藏、历史、统计在首屏均有入口。
- 收藏和历史预览不重复发起业务请求。
- 路由高亮为“我的”。

### 点播

- 竖屏播放器宽度占满内容区。
- 播放器下方能直接切换当前附近集数。
- 全部选集、换源、详情均可在两次点击内打开。
- 横屏时导航和非播放内容可以隐藏。
- 播放状态、进度、换源和收藏逻辑与桌面端一致。

## 20. 推荐决策

建议按阶段一到四执行，不直接一次性重写所有移动页面。

最先实施全局导航和点播页沉浸模式，原因是这两部分决定移动端整体结构，也能消除当前最明显的底栏拥挤和播放空间不足。首页与分区的卡片、数据和缓存基础已经可以复用，后续主要是展示密度和内容编排调整。
