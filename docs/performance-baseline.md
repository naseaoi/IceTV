# 性能基线

采集方法与固定场景，目的是让优化前后的数字可比。数字本身不入库，每次自行采集对比。

## 自动基线

运行：

```powershell
pnpm perf:baseline
```

该命令使用隔离的内存数据，不写入正式 SQLite 或 MySQL。固定场景包括：

- 10 万条播放会话的 7 段区间统计和 Top 统计
- 1500 次包含剧集与描述的搜索缓存写入
- 10 万次 VOD 分片容量预留

保存输出中的耗时、缓存条目数、估算字节数和淘汰次数。耗时只和同一机器、相同 Node 版本及相同电源模式下的历史结果比较。

## 浏览器基线

使用生产构建，并固定 Chrome 版本、视口和网络设置。

| 场景              | 固定条件                            | 记录指标                                            |
| ----------------- | ----------------------------------- | --------------------------------------------------- |
| 冷 Service Worker | 清除站点数据后首次访问，Fast 4G     | 预缓存请求数、传输字节、安装耗时                    |
| 登录页            | 390 x 844、CPU 4 倍降速、录制 10 秒 | DOM 节点、长任务、脚本、渲染、GPU 内存              |
| 长时间 VOD        | 同一视频播放 30 分钟并拖动 10 次    | 分片请求、Cache Storage 操作、主线程长任务、掉帧    |
| 远程 MySQL        | 10 万条播放会话、固定网络区域       | `/api/playback-stats/summary` 的 p50、p95、查询次数 |

每次优化前后各执行 5 次，丢弃第一次预热结果，记录剩余 4 次的中位数。冷 Service Worker 场景不丢弃第一次。
