# 消息与追更边界

只保留当前生效、容易误判的约束。实现见 `src/lib/tracking-sql.ts`、`src/lib/play-records.ts` 与 `src/components/messages/`。

## 数据与查询

- 未读状态从播放记录推导，不另存一份布尔值。查询按 `username` 走复合主键范围，不扫描其他用户记录；仅在单用户查询出现明确瓶颈时考虑派生列，并保证写入、导入与迁移同步。
- SQLite / MySQL 共用 `tracking-sql.ts` 的谓词，只在数字、时间和布尔读取原语中区分方言；不要在两套存储里分别改未读条件。
- `group_index` 与 `group_total` 同时有效时才使用组内刻度；已读基线必须与当前集数、总集数使用同一刻度。
- 旧分组标签可兼容，但**已推进的已读基线不批量回退到观看集数**：无法区分漏提醒与用户主动已读，回退会制造重复提醒。保留已有基线，只提醒后续新增集数。

## 摘要刷新

- 摘要不增加短 TTL 服务端缓存；重复刷新由单标签页内的可见性节流和消息事件防抖合并，不提供多标签页请求去重。
- 删除失败时，列表可能已乐观移除，但不会派发 `messagesUpdated`；角标由下一轮可见页面轮询恢复，不要求同步回滚所有视图。
- 连续快速切换标签页时，补拉可能被最小间隔挡住；停止切换后恢复正常轮询，不为每个 focus 事件单独请求。

## 测试边界

- fake pool 只验接线，不执行数据库 SQL。真实 MySQL 的运行方式见 [AGENTS.md](../AGENTS.md#测试)。
- 真实 MySQL 当前覆盖追更查询、双后端一致性、共享缓存和资源租约；不能据此推断整个 `IStorage` 接口均已覆盖。
- MySQL 的 JSON 布尔读取不能用数值比较替代字符串 `'false'`；无效数字字符串的 CAST 可能转成 0 而非抛错，输入校验与跨后端用例仍须保留。
