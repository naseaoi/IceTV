# 源站、搜索与健康度约束

改搜索、源站接入、源站健康或探测前先读本文。

## 搜索

- 源适配器只提供解析能力。用户侧搜索、详情和逐集解析须先经 `getAvailableApiSites()`，仅使用后台已配置、已启用且账号有权访问的源；未配置与禁用源均不开放。后台可单独检测禁用源，供管理员判断能否重新启用。
- 后台检测、搜索聚合、西瓜标题过滤与搜索建议共用 `search-text.ts` 的简繁归一化匹配，保留上游原标题；快速起播和换源只在候选比较时转换，持久化作品身份 `normalizeWorkTitle()` 保持原规则。
- 每源先请求原关键词，成功但没有匹配项时，繁体或混合输入转简体补查一次，补查只取第一页；简体输入不转繁体补查（多数源站只有简体，繁体源的标题仍可经归一化匹配），转换后字形相同时不补查。默认按标题子串判断命中，quick 沿用播放候选的标题、年份与类别过滤，`search/one` 按简化后的标题相等判断。两次查询共用消费者取消与外层时间预算，异常和接口拒绝搜索直接按失败处理；分页与缓存分别使用实际请求词，避免不同关键词的页混用。上游独有译名、别名不属于简繁转换范围。
- 普通 CMS 的真实搜索、分页、健康探测与后台检测共用 `cms-search.server.ts` 的 URL 构造和载荷校验，保留源地址已有查询参数；关键词沿用 `encodeURIComponent` 语义，空格编码为 `%20`。列表中的无效条目单独跳过，非空列表全部无效才判失败；稀饭与天涯搜索沿用这一容错边界，稀饭详情仍严格校验。
- 聚合执行 `runSearchAggregation()`，聚合缓存 `src/lib/search-cache.ts`，失败源冷却 `src/lib/search-aggregate.ts`。不要在页面层重新实现聚合、缓存或失败冷却。
- 流式搜索的进程内任务复用普通搜索聚合键：去除首尾空白的关键词、最大页数、内容过滤开关，以及鉴权后可见源的有序 key / 名称 / API / detail；权限通过可见源集合隔离，重试再按目标源集合分区。逐源事件只过滤、序列化一次，后到订阅者用游标回放已有事件并继续接收新事件；任务结束即移出在途表，完整非空结果经数据库共享缓存发布，普通搜索与后续流式搜索复用聚合缓存。逐源事件只在单实例共享，跨实例仍由搜索页共享租约合并回源。
- 流式消费者取消只释放自己的订阅，最后一个离开才中止聚合与后续调度；已启动的共享页/特殊源 loader 沿用独立消费取消语义，继续在既有回源超时与资源额度内完成。取消的聚合不保存部分结果。进程内聚合准入、流式任务数、订阅数及事件回放字节均有硬上限；消费者流按需拉取共享回放，不另建无界事件队列。
- 搜索并发闸门位于普通页与特殊源真实 loader 内，在缓存查询和在途合并之后申请；页缓存命中与等待已有 loader 的消费者不占回源槽。真实 loader 的排队有数量与时间上限，回源超时从取得槽位后开始；外层单源消费预算仍限制消费者等待（包括回源排队），预算耗尽只上报本次失败源、不触发整源冷却，请求级聚合准入独立保留。
- 搜索页聚合视图的标题、年份选项与匹配都取聚合代表条目；来源按组内包含关系匹配，并将播放候选限定到所选源，保持代表标题与年份。非聚合视图沿用原始结果；切换视图或聚合结果变化后，当前视图中已不存在的筛选值恢复为全部。
- 普通搜索页共享层 `search-page-shared-v2` 保留跨实例租约合并：非空成功页新鲜期为 10 分钟，与本地成功页一致；空结果和失败为 60 秒。共享层无陈旧窗口，避免本地页后台刷新再次取得共享旧值、延后真实回源。本地成功页仍有额外 10 分钟陈旧窗口。共享层近端内存继续使用较小的 `search-empty-pages` 预算，与本地成功页缓存分开计额；数据库统一受共享容量目标约束，预算名称不代表只持久化空页。直接探测与强刷保持绕过共享层。
- `/api/search` 命中新鲜缓存直接返回；命中过期缓存先返回旧结果再后台刷新。
- 单源异常（含回源额度申请失败）不让整体搜索失败，接口仍可 200；判断源是否可用看健康数据，不看搜索接口状态码。
- 失败源与空结果分开上报：`searchFromApi()` 默认把第 1 页失败（超时、非 2xx、网络或 JSON 异常，含页缓存里的 `timeout` / `forbidden` / `invalid`）当空结果返回；聚合传 `reportFailure` 让它抛 `SearchSourceUnavailableError`，经 `collectSearchAggregation()` 记入 `failedSources`，不进整源失败冷却。maccms 无结果时返回 `list: null` 且 `total` 为 0，按空结果处理；普通源返回失败码、其他无效 `list` 结构或非空列表全为脏条目时，健康样本记 error，并写 `invalid` 页缓存（60 秒保鲜、60 秒陈旧窗口）；陈旧命中先返回失败并后台刷新。超时与 HTTP 403 沿用 `timeout` / `forbidden` 页缓存（10 分钟保鲜、10 分钟陈旧窗口）；普通搜索共享加载还会短期保存失败结果，直接探测与强刷绕过共享加载。giri / xgcartoon / xifan / tyyszy 回源失败或解析异常同样在聚合中上报 `SearchSourceUnavailableError`，记入 `failedSources` 且不进整源失败冷却；真正无结果返回空数组。本站资源额度不足或上游出口冷却抛出的 `ResourceLimitError` 同样只记入 `failedSources`、不进整源失败冷却：它反映本站负载或单个出口被限流，整源冷却会让高峰期的正常源对本实例所有用户缺席 5 分钟，上游 429 已由按「出口 + 域名」共享的冷却阻止重复发送。默认搜索与仅取第一页的搜索入口保持失败返回空数组，供 quick、搜索建议和详情回退使用。
- 聚合缓存条目同时保存 `failedSources`：`/api/search` 返回 `totalSources` 与 `failedSources`，流式搜索命中缓存时为它们重放 `source_error`。客户端重试只经 `/api/search/ws?retry=<源 key,…>` 重搜失败源：跳过失败冷却与第 1 页缓存，结果经 `mergeRetriedSearchAggregate()` 替换本实例缓存中这些源的部分；缓存不存在时不凭局部结果新建。
- `/api/search/quick` 保留用户可用源、作品/年份/类别过滤、健康等级排序、最多 10 源与 4 槽竞速；同等或更好健康等级的直连源保留 1500ms 优先窗口。普通源搜索结果具有源/id、标题、封面、四位年份、源名称、非空 HTTP(S) m3u8/mp4 剧集及逐集标题，且不带分组、关联版本或版本标签时，直接参与竞速；逐集解析型特殊源、懒地址与字段不完整的候选仍先取详情，保留详情字段覆盖与失败后的搜索结果回退。
- quick 胜者的搜索快照不作为完整详情写缓存；胜出后非阻塞调用共享详情加载，保留详情缓存填充。客户端 quick 分支保存快照并起播；当前的快照后台校验仅在按源/id 读取快照的入口执行，quick 首次起播本身不保证收到新详情。
- quick 关联客户端取消，胜出或取消后停止候选等待和后续源调度。每源搜索与详情共享 20 秒消费预算，失联源缩短至 5 秒；1500ms 直连窗口独立于单源预算。共享搜索页与详情采用消费者独立取消：取消不传入共享 loader，已启动加载继续填缓存，其他消费者照常获取结果；结束的 quick 不再尝试输家第二候选。

## 成人源与 NSFW

- `SourceConfig.nsfw` 为可选布尔值；站点 `DisableYellowFilter=false` 时，`getAvailableApiSites()` 对所有角色及内部元数据读取排除该源，搜索、流式重试、quick、单源搜索、建议、换源、详情、逐集解析及源选择上下文均沿用此入口。普通源继续使用条目分类关键词过滤；豆瓣与 Bangumi 分类属于独立目录数据。
- 播放页的路径式与查询式固定源入口在服务端检查成人源策略，避免本地详情快照先起播。清单、密钥与分片代理在签名或会话放行前检查携带的源标识；后台管理与手动检测保留源可见性，定时健康探测跳过被过滤源。
- 订阅 `api_site.<key>.nsfw` 接受布尔值；同 key 已有显式本地值（含 `false`）优先，订阅仅补齐未设置值。后台取消标记保存 `false`，以保留本地选择；配置文件导出保留这两个布尔值。订阅本身缺少标记时既有值保持不变。
- 配置读取沿用配置缓存 TTL；跨实例或开发模式不同路由包的切换可见性以各自缓存刷新为界。通用 URL 代理只识别请求携带的源标识，任意 CDN URL 无法反推出所属视频源；NSFW 是站内源与内容入口策略，不是外网访问控制。

## 源站健康

- 质量分与等级由 `src/lib/source-health.server.ts` 汇总、`src/lib/source-quality-policy.ts` 计算，阈值、样本门槛、探测关键词与并发只在策略文件定义。搜索、播放可用与播放流畅度达到各自窗口样本门槛时，质量分取所有合格维度平滑率的最低值乘 100；仅一项达标时只用该项。搜索在生产中普遍可用，区分播放质量的能力有限，短板评分让低播放可用率直接影响等级。评分用平滑比率，接口返回原始比率供展示；50/85 分阈值、优质耗时门槛、失联判定及窗口样本门槛保持独立。后台手动排序决定面板展示顺序，服务端健康排序只在同一等级内沿用配置顺序作为兜底。健康等级聚合所有用户的结果，客户端起播与自动换源优先使用当前浏览器的有效可靠性证据，具体比较规则见[播放选源偏好](playback.md#线路检测)。
- 搜索样本在 `downstream.ts` 的 `fetchAndCacheSearchPage()` 第 1 页与后台手动检测采集；手动检测结束后立即刷新样本缓冲，成功的有效结果记 ok、无结果记 empty，请求、超时或解析失败记 error。缓存命中、加载器父级中止、`ResourceLimitError` 不计。giri / xgcartoon / xifan / tyyszy 等特殊源在 `searchSpecialSourceWithSample()` 采样：用户搜索只在共享 loader 真实回源时记录，后台手动检测与定时探测同样记录；适配器抛错记 error，返回空数组记 empty。特殊源若无搜索样本，只能靠播放上报日定级，长期停在 `insufficient` 而排在普通源之后，排得靠后又更难攒到播放样本。共享加载的消费者取消不算加载器中止，后续完成的真实回源照常采样。新增搜索路径若绕过该函数，质量分会静默缺样本。健康样本不区分失败原因；真实回源失败同时输出 `[search.failure]` 警告日志，记录源 key、页码、原因（`http` 带状态码、`invalid-payload`、`timeout`、`upstream-cooldown` 即本次收到 429 / 带 `Retry-After` 的 503、`request` 带底层错误码，URL 校验失败另记白名单内的固定原因（如 `DNS lookup failed`、`Blocked destination`、`Redirect not allowed`；未知原因用通用说明），特殊源 `adapter` 带错误信息，普通与特殊源的 JSON 解析错误均只记固定说明，因其消息会带正文片段）与耗时，不含关键词与地址；冷却命中、本站限额与父级取消不记。排查持续失败的源（限流、超时还是地区封锁）先查这条日志。
- 搜索样本先在进程内累加，距上次写库超过间隔后由下一次记录触发写库；读报告前只刷新本模块实例的缓冲，其他实例或路由包的样本要等它们下一次记录才可见。
- 播放指标统一称「播放可用（含测速）」：真实播放意图的最终结果与换源面板测速的成功、失败均经 `POST /api/source-route-stats` 的 `outcome` 写入 `source_health_play`，按「源 × UTC 日 × 上报者」聚合。同一上报者当天有任一成功即记成功日，评分按上报者日而非请求次数计算。上报者是用户名的 HMAC，不存用户名，因此不纳入删号与合并，靠 cron `metadata` 任务按保留期清理。线路尝试单独经 `stat` 按首选 / 回落记录，只统计线路成功与网络类失败，后台据此显示直连、代理与「直连失败后代理挽回」成功率，配合服务端代理失败原因给出改线路建议（规则见 `src/features/admin/components/tabs/video-source/sourceRouteView.ts`，样本不足 20 不下结论）；直连失败后代理成功的播放意图记成功，不将单次线路失败写入健康数据。整个上报接口按规范用户名每分钟最多 120 请求，超限返回 429 与中文提示；限流为进程内固定窗口，多实例各自计数。
- 播放流畅度由同一上报接口的 `smooth` 接收增量，可与线路尝试、最终结果独立或合并上报；全零增量成功返回并跳过写入。采集口径见[播放](playback.md)。判定先跨线路与媒体类型汇总到「源 × UTC 日 × 上报者」，观察不足的日不计；同一上报者同日在至少 3 个源卡顿且没有任何流畅源时，排除其当天全部样本，避免个人网络受限拉低全站评分。有效样本达到 20 个上报者日且至少 5 个不同上报者才启用流畅维度，未达门槛时保留原评分；流畅分使用与可用率相同的先验平滑，展示比率使用原始流畅日占比。卡顿率与每 10 分钟卡顿次数仅汇总有效日，未知等待只供诊断；后台分层诊断保留网络受限样本。流畅度不改变失联判定、优质耗时门槛、最近可用日期与告警。
- 固定代理成功率低且主因达到样本门槛、集中为上游 403 或连接中断时，后台建议改为直连；其余固定代理低成功率仍建议自动。主机冷却命中沿用真实失败原因给客户端决策，服务端原因样本只计实际回源失败，避免冷却请求放大故障占比；客户端跳过的线路同样不新增线路尝试。冷却与自动模式直连优先的边界见[播放线路检测](playback.md#线路检测)。
- 每日状态覆盖窗口内每个 UTC 日，旧日到新日排列，无足够样本的日为 `none`。当日搜索至少 5 次、播放至少 3 个上报者日才纳入对应维度，取合格维度原始可用率的较低值：至少 85% 为 `ok`、至少 50% 为 `degraded`，其余为 `down`。每日状态不使用平滑率、耗时或失联判定，窗口等级与每日状态各自按对应口径计算。当日流畅度有效上报者至少 3 个且有效观看合计至少 30 分钟时，流畅日占比低于 85% 只把 `ok` 降为 `degraded`，其余状态保持原值。
- 默认 7 日完整报告经 `getCachedSourceHealthReport()` 在进程内缓存 5 分钟并合并在途读取；等级映射与用户接口共用这份缓存。读取失败缓存失败状态到同一 TTL，等级排序降级为空映射，用户接口返回 503；后台 `/api/admin/source-health` 直接读取实时报告并刷新当前模块样本缓冲，手动检测完成同时重新拉取报告与告警。
- `GET /api/source-health` 要求活跃登录，按 `getAvailableApiSites(username, config, userAccess)` 过滤源并返回 `private, no-store`。`insufficient` 始终省略；失联源直接公开，其余等级需窗口内至少 20 个播放上报者日。公开内容仅含等级、原始搜索可用率、播放可用率、流畅率、最近可用日期与 7 个每日状态点；播放上报者日不足 20 时公开播放比率为 `null`，流畅维度未达窗口门槛时流畅率为 `null`；源名、样本数量、分层诊断与评分留在后台。
- 播放页换源面板经 `src/features/play/lib/sourceHealthSummary.ts` 读取该接口，客户端缓存 5 分钟，失败不缓存且不显示徽标。行内每源最多一个徽标，优先级为「失联 > 不稳 > 卡顿多 > 稳定」：失联、低质先显示对应徽标，其余等级卡顿时显示「卡顿多」，优质且不卡顿显示「稳定」，普通且不卡顿不占行内空间。播放页与后台共用策略文件的 `isSmoothRateStuttering()`：流畅维度达样本门槛且原始流畅率低于 `SOURCE_HEALTH_DAILY_OK_RATE`（85%）才标记卡顿；公开接口已将未达门槛的流畅率置为 `null`，播放页直接按该值判定；「卡顿多」沿用低质的琥珀色，弹窗在等级文字后追加同色标记；「全站近期参考」由徽标悬停提示与弹窗说明交代，不在每个徽标重复；点击徽标打开「源站近况」，标明全站近 7 天参考。徽标不参与面板排序，面板仍按本机测速与可靠性排序，避免全站结论覆盖用户自己网络下的实测。
- 搜索、流式搜索、快速起播、搜索建议经 `getSourceHealthTiers()` + `rankSourcesByHealth()` 按**等级**排序后再调度或截取。不按分数排：分数随每批样本变化，而搜索聚合缓存键包含源顺序，按分数排会让缓存反复失效。新增按源顺序取舍的入口须同样排序；健康数据读取失败时降级为配置顺序。
- 样本先在进程内缓冲再批量写库；写库持续失败时缓冲只保留健康数据保留期内、最多 4096 个「源 × 日」桶，超出丢弃最旧样本，不阻塞搜索。
- 失联源仍参与搜索，只缩短单源消费预算；消费者预算到期不直接写失败样本。独立共享加载继续按实际回源结果采样，探测请求自身的父级中止不计样本，恢复也可由定时探测发现。
- 失联源只标记，不自动停用：停用后不再产生样本，恢复无法被发现。
- 管理员告警（`src/features/admin/lib/admin-alerts.server.ts`，接口 `/api/admin/alerts`）只读已有数据，不额外回源。源站持续失效由健康日桶推导：最近一次成功日之后的失败达到策略常量的天数与次数才告警；同一天任一成功（含空结果搜索、播放成功）会抵消当天的失败。日桶没有请求级先后顺序，告警开始时间是首次失败日的 UTC 零点。已停用的源不告警，所以告警消失只表示条件解除，不一定是服务恢复。
- 告警还包括订阅定时更新失败（仅站长可见）和待处理举报。客户端在根布局为管理员轮询，在后台入口与对应 tab 显示角标；每条告警出现、解除各提醒一次，持续中不重复。已提醒记录按账号与角色存在浏览器本地，并保存源名供解除提醒使用；旧记录缺少名称时使用通用解除文案。
- 告警的出现提醒带「查看」，跳到对应 tab（`getAdminAlertHref()`）；源告警带 `source` 参数，视频源列表落地后清空搜索与筛选、滚到该行短暂高亮并移除参数。源告警附带判定依据（`sourceDetail`），列表据此在行上显示「持续失效」，并提供「告警中」筛选；它与近 7 天质量等级是两套口径，告警源的质量等级可能仍是普通。手动检测完成后的刷新规则见上面的报告缓存约束。

## 探测

- 后台手动检测按源类型调用真实搜索入口，特殊源走各自适配器，普通 CMS 校验成功码与 `list` 结构。成功响应有匹配项显示「有效」，成功但没有匹配项显示「无搜索结果」；接口拒绝搜索、格式异常、超时或连接失败显示「无法搜索」。西瓜卡通页面无法解析且没有明确的零结果标记时算失败，天涯搜索页缺少结果容器 `#movieGrid` 时同样算失败，拦截页不当作空结果。

详情与逐集解析的 HTTP 入口经 `withAuthenticatedSourceProbeBudget()` 鉴权后，将可信 `ActiveUserInfo` 作为函数参数传给未导出的内部 handler；测速包装复用这次鉴权，不从请求头读取权限上下文。测速额外的资源租约与普通回源预算同时生效，内部请求携带包装层的取消信号；共享加载只取消当前消费者等待。

由 cron `metadata`、`all`、`source-health` 执行（调度见 [部署](deployment.md#定时维护与源站探测)）。只请求启用源的搜索第一页，跳过搜索缓存读取，沿用真实搜索的样本分类与回源资源额度，结束后刷新样本缓冲；特殊源直接调用适配器搜索、不读写特殊源共享缓存，关键词按 UTC 日期轮换。

## 特殊源注册与逐集解析

特殊源统一注册于 `src/lib/downstream-sources/registry.server.ts`：站点识别、搜索、可选详情、可选逐集解析与 quick 搜索快照起播能力共用一份声明。站点识别只看 API 主机名，不匹配路径与查询参数，避免普通 CMS 地址里出现特殊源域名时被误判。适配器搜索失败时抛出带具体原因的 Error（状态码、超时、底层错误类型，多入口逐个列出，不含关键词与完整地址），父级取消返回空数组，`ResourceLimitError` 原样抛出；由 `searchSpecialSource()` 统一转为 `SearchSourceUnavailableError`，原因留给 `[search.failure]` 日志。搜索、后台检测、详情、逐集解析和 quick 均按注册表分派；未声明详情函数时沿用普通 CMS 详情及配置的详情页回退。`canStartFromSearch` 表示允许跳过详情等待，候选仍须通过 quick 的字段与媒体地址检查；它与是否支持逐集解析分开声明，天涯的批量详情搜索结果允许直接起播。

逐集解析统一用 `icetv-lazy://`：详情阶段返回懒地址，播放时经 `/api/episode-url` 解析。接入逐集解析源时：

1. `src/lib/lazy-episodes.ts` 新增 kind 与路径白名单正则；该模块保持客户端可导入，只定义地址协议，不导入服务端注册表。
2. 源适配器的 `episodes` 用 `buildLazyEpisodeUrl(kind, path)`，导出逐集解析函数，并在注册表声明同名 kind 及解析器。
3. 注册表的映射类型要求每种 `LazyEpisodeKind` 都有对应解析器，遗漏会在 typecheck 报错；`special-source-registry.test.ts` 遍历注册表验证搜索、后台检测、详情、逐集解析与 quick 的实际分派，以及测试站点之间识别互斥。新增适配器须补充该测试的站点、函数与合法路径样例。路由同时核对可用源与 kind，未知或错配 kind 返回 400。

不要在详情阶段全量抓播放页，不要绕过 `/api/episode-url` 在客户端直接解析源站地址。

- 稀饭动漫的源地址填写 `https://next.xifanacg.com`，游客 API 使用源站网页公开的 publishable key。详情按 `CS` 备用线路（全站编号 `2`）→ `xfy2` 旧番主线（编号 `5`）→ `xfxf1` 新番主线（编号 `4`）选择首条有剧集的线路；逐集解析同时核对所选线路编号与代码，避免上游 fallback 换线。三者共用后台播放路由，支持浏览器直连，`auto` 沿用播放器的网络失败回落。CS 返回 HLS，主线返回游客 API 签发的签名 MP4，沿用签名地址短期本实例缓存；新番主线重定向至网盘，要求媒体请求省略 Origin 与 Referer，由全站文档策略和原生播放器处理，约束见[播放](playback.md#线路检测)。无需额外取址服务器，代理模式复用现有媒体中转。该源与其他特殊源一样复用共享搜索缓存，定时探测与后台手动检测调用其游客搜索 API。

- 天涯资源（`tyyszy`，API `https://tyyszy.com/api.php/provide/vod`）的 API 搜索被源站关闭，搜索改用网页提取 id 后一次 API 批量详情，按网页顺序返回；与其他特殊源一致仅取第一页，详情与播放地址继续沿用普通 CMS 路径。视频 CDN 只放行浏览器直连，后台播放模式须设为「直连」。

解析结果与特殊源搜索跨实例共享，均按源配置（`getSourceCacheKey()`）分区：

- `src/app/api/episode-url/cache.ts`：不带签名参数的播放地址进共享缓存 `episode-url-v1`，30 分钟新鲜、2 小时陈旧；带签名参数的地址只留在本实例。`refresh=1` 强刷跳过两级缓存重新解析，需登录并受每账号每分钟 8 次的 `episode-url-refresh` 额度限制；同键强刷在途合并，结果写入本实例缓存并优先于共享缓存，不回写共享缓存，强刷进行中或完成后迟到的普通加载不能覆盖它。服务端与浏览器懒解析缓存共用 `src/lib/signed-url-params.ts` 的签名有效期规则：最长 5 分钟，能解析签名到期时间时以较早者为限，签名地址到期后重新加载。共享缓存的结果格式或有效期变更时升级缓存名版本。依赖 Cookie、会话或出口 IP 的解析结果不能进共享缓存。
- giri / xgcartoon / xifan / tyyszy 搜索经 `loadSpecialSourceSearch()`（`src/lib/search-cache.ts`）共享非空结果 10 分钟。失败由 loader 抛出，失败与空结果均不缓存；失败源重试沿用聚合入口。
